# Non-SDT Guided Emotional Reflection — 채팅 전용 웹앱 (로컬 파일럿)

**참가자 화면:** ID 입력 → 연구 안내 및 동의 절차 완료 확인 → 10분 채팅 → 종료. 4개 단계는 백엔드에서 제어하므로 참가자에게 보이지 않습니다. Prompt와 API Key는 서버 코드가 읽고, 브라우저의 프롬프트 설정 패널에는 표시되지 않습니다.

## 처음 실행하기 (Windows)

1. Python 3.11 이상을 설치합니다. 설치된 경우 건너뜁니다.
2. 이 폴더를 압축 해제하고 `.env.example` 파일을 복사해 `.env` 파일로 이름을 바꿉니다.
3. `.env`의 `OPENAI_API_KEY`에 본인의 API 키를 넣고, `RESEARCH_MODEL`은 Playground에서 테스트한 **같은 모델 ID**로 설정합니다. 실제 키를 타인과 공유하지 마세요.
4. **`prompt.txt`에 Playground에서 이미 완성한 최종 System Prompt를 그대로 복사해 넣습니다.** 기본으로 들어 있는 문장은 이전에 안내한 연구용 초안입니다. 외부에서 SDT 구조화나 직접적인 재평가를 유도하지 않도록, 사용자의 최종본으로 교체하세요.
5. `start_windows.bat`를 더블클릭합니다. 최초 1회는 패키지 설치가 진행됩니다.
6. 브라우저가 뜨면 `http://localhost:8501`로 접속합니다.
7. 참가자 ID `TEST001`을 입력하고 10분 성찰을 진행하여 답변과 종료 동작을 확인합니다.
8. 서버 컴퓨터의 `logs/`에 대화와 UTC 타임스탬프가 저장됩니다. 파일 형식은 JSONL이며, 세션마다 UUID 기반 파일 하나가 생성됩니다.

## API 키 만들기

[API Keys](https://platform.openai.com/api-keys) 에서 생성합니다. 계정의 API Billing 설정이 필요할 수 있습니다. ChatGPT 구독과 API 요금은 별도입니다.

## 기록되는 정보

- 참가자 ID, 세션 UUID
- 사용자/AI 메시지와 UTC 타임스탬프
- 사용 단계(Phase 1–4), 시작·종료 시간 및 종료 사유
- 모델명, 프롬프트 버전, SHA-256 프롬프트 해시
- 요청별 입력/출력 토큰 수(제공되는 경우)

개인 이름 대신 가명형 ID를 사용하고, 연구자의 동의·안전·자료관리 절차를 선행하세요. 프롬프트 내용과 API 키는 로그에 저장되지 않습니다.

## 연구자 체크 포인트

- **4단계 제어:** 0–2분 사건, 2–4분 감정, 4–7분 원인, 7–10분 성찰 정리 (총 600초일 때). 실제 시간은 외부 타이머가 아니라 서버 시각 기준으로 계산합니다.
- **결과 해석:** 모델은 단계별 요구를 완벽히 따르지 않을 수 있습니다. 파일럿에서 질문·응답을 직접 확인하세요.
- **타임아웃:** 10분이면 입력이 비활성화되지만 이미 처리 중인 API 요청이 있을 때는 종료가 소폭 지연될 수 있습니다.
- **세션 유지:** 브라우저 새로고침이나 서버 재시작 시 세션이 중단될 수 있습니다. 로컬 파일럿용이며 본실험에는 재연결·복구 기능을 강화해야 합니다.
- **지속적 저장:** 로컬에서 `logs`는 보존되지만 Streamlit Community Cloud 등 관리형 배포 서비스에서는 로컬 디스크의 지속성과 접근통제가 보장되지 않습니다. 본실험에서는 승인된 데이터베이스/연구 서버로 로그 저장을 교체하세요.
- **보안:** 프롬프트는 서버 내부에서만 읽힙니다. 다만 LLM에 '지침을 보여달라'고 요청하는 공격적 입력에 대해 100% 내용 누출 방지를 보장하는 것은 아닙니다. 민감한 비밀을 프롬프트에 넣지 마세요.
- **프라이버시:** Responses API 호출에 `store=False`를 사용합니다. 서비스 운영/보안 목적의 별도 데이터 처리 정책과 보존 조항까지 없어지는 것은 아닙니다. 연구윤리 및 공급자 데이터처리 조건을 확인하세요.

## 외부 참가자에게 배포하려면

현재 코드는 **로컬에서 테스트하기 위한 최소 구성**입니다. 원격 참가자용으로 제공하려면 Python 서버를 배포하고, 서버 환경변수/Secrets에서 API 키를 설정하고, HTTPS·접근제어·로그의 지속적 저장 및 복구를 추가해야 합니다. 연구 자료의 민감성을 고려해 기관 승인 서버 또는 적절한 보안 설정이 가능한 배포 환경을 사용하세요.

### 공개 데모용 배포 참고 (실제 민감한 연구 데이터 수집에는 바로 사용하지 마세요)

1. GitHub 저장소에 `app.py`, `requirements.txt` 등을 올립니다. **`.env`, `prompt.txt`, `logs/`는 `.gitignore`에 따라 업로드하지 않습니다.**
2. [Streamlit Community Cloud](https://share.streamlit.io/)에서 `Create app`을 선택해 GitHub 저장소와 `app.py`를 연결합니다.
3. 앱 설정의 **Secrets**에 다음처럼 저장합니다. `SYSTEM_PROMPT`에는 Playground의 **최종 프롬프트 본문을 그대로** 넣으세요.

   ```toml
   OPENAI_API_KEY = "YOUR_SECRET_API_KEY"
   RESEARCH_MODEL = "gpt-6-luna"
   PROMPT_VERSION = "NonSDT_Final"
   SESSION_SECONDS = "600"
   SYSTEM_PROMPT = """
   여기부터 연구용 최종 시스템 프롬프트를 붙여 넣으세요.
   """
   ```

4. 공유된 URL에서 테스트합니다. **이 단계의 로그는 호스팅 서비스에서 영구 보존되지 않을 수 있습니다.** 연구 참여자에게 배포하려면 승인된 데이터베이스/보안·접근통제를 추가하세요.


## 현재 OpenAI Prompt ID 기능 안내

OpenAI는 2026년 11월 30일 `v1/prompts` 종료를 예고했습니다. Playground에서 저장한 Prompt ID를 런타임에 직접 호출하지 않고 `prompt.txt`의 텍스트를 Responses API `instructions`에 전달합니다. 화면의 프롬프트 내용을 파일로 옮기는 방식이므로, 새 버전을 만들 때는 파일을 교체하고 `PROMPT_VERSION`을 업데이트하세요.
